- 文档版本：1.2

- 产品阶段：V1 需求定稿；未进入编码
- 工作名称：Log Investigator，最终产品名不影响本 PRD
- 决策依据：需求访谈中确认的 26 项选择、远程破坏性命令禁令、故障知识库增补，以及提示词粘贴 / `@本地日志文件` / traceId 远程查询三种日志入口的明确

> 本文的“已确认”代表访谈已达成共识；“推荐默认值”用于补齐可配置的运行参数，不代表已经实测。本文不声明 Pi、真实登录脚本、模型网关或真实故障案例已经完成联调。

## 1. 产品定位与目标

### 1.1 定位

面向 Java / Spring Boot / Spring Cloud 开发者的专用、轻量、只读故障诊断 CLI。根据报错日志和本地仓库源码，解释故障触发机制，输出有证据的原因及可操作的解决方案。

核心链路：提示词直接粘贴日志 / `@本地日志文件` / 输入 traceId 经 JumpServer 查询日志 → 按需检索本地源码与已确认故障经验 → 建立当前证据链 → 输出诊断与修复建议 → 人工确认后沉淀故障知识。

### 1.2 V1 目标

1. 降低手工登录、筛选日志、查找源码和串联异常链的成本。
2. 覆盖 Java 异常堆栈与没有堆栈的业务失败，而不只复述错误信息。
3. 区分表层异常、直接原因、可证实根因和外部依赖边界。
4. 在权限、时间、数据传输和查询规模均有边界的前提下自主取证。
5. 让团队成员安装后使用自己的脚本、网关凭证和本地仓库，不建设中心服务。
6. 把经人工确认的故障根因、处理过程与验证反馈沉淀为可检索经验，减少重复排查；历史经验仅提供线索，不替代本次故障证据。

### 1.3 非目标

- 不修改业务仓库，不自动生成落盘补丁，不提交代码、不创建 PR、不部署。
- 不重启服务，不变更服务器文件、权限、配置、进程或系统状态。
- 不读取远程部署配置、环境变量，不查询数据库、缓存、监控或进程运行状态。
- 不跨服务、跨仓库、跨服务器追查，不做实例发现和集群扫描。
- 不负责拉取仓库、切换分支、构建项目、运行测试或复现业务请求。
- 不做 Web 管理平台、后台常驻服务、集中账号或集中会话存储。
- 不做多 Agent 编排、向量数据库或预建全仓索引；故障知识库仅采用轻量本地文件，不建设集中知识平台或自动同步服务。
- 不承诺任意输入都能得出确定根因，不把模型自报百分比当作可信度。

## 2. 使用者、平台与配置边界

### 2.1 使用者

团队内需要排查应用故障的开发者。使用者自行准备可运行的登录脚本、可访问的本地仓库、获准使用的模型网关及授权凭证。

### 2.2 已确认边界

| 项目 | V1 约定 |
| --- | --- |
| 客户端 | 独立专用 CLI，内部薄封装 Pi SDK，不要求先安装通用 Pi CLI |
| 平台 | 仅 macOS；交付时明确已验证的系统、芯片架构和运行时版本 |
| 使用方式 | 连续对话，支持追问、补充信息、继续取证、中止和恢复 |
| 日志输入 | 提示词直接粘贴、`@本地日志文件`、traceId 经 JumpServer 远程查询；可组合提供，分别记录来源 |
| 单次诊断 | 单服务、单本地仓库、单台远程服务器 |
| 配置数量 | 每位成员一组本地配置，不做命名 profile 切换 |
| 技术栈 | Java / Spring Boot / Spring Cloud，可读取仓库内相关构建与配置源码 |
| 代码版本 | 用户准备对应版本；Agent 记录本地版本与工作区状态，不自动修正 |
| 模型 | 已有 OpenAI 兼容网关；一次诊断使用一个已配置模型 |
| 认证 | 用户脚本全自动完成登录，停留在目标日志目录的远程 Shell |
| 远程权限 | 只查询批准目录内的日志及必要文件元数据，非日志数据不开放 |
| 故障知识库 | 应用独立目录中的本地 Markdown 文件；候选总结经人工确认后入库，检索不扩大单服务、单仓库诊断范围 |

### 2.3 本地配置内容

- 本地仓库根目录。
- 用户可信的一键登录脚本路径及必要的固定启动参数。
- 预期目标机器标识与远程日志根目录，用于展示和核对，不自动发现其他机器。
- 网关地址、明确的 API 类型、模型名称及凭证引用；不把密钥写入仓库或诊断报告。
- 脱敏规则、查询预算、输出上限及会话保存位置。

配置和工具运行数据位于应用自己的用户目录，不写入业务仓库。仓库只读与应用保存自身配置、脱敏记录、经用户确认的故障知识并不冲突。知识库与临时会话分目录保存，路径位于应用用户目录内，不允许知识条目指定任意写入位置。团队使用统一安装与配置格式，但各自保管凭证、会话与本地知识库；V1 不自动共享、上传或同步知识条目。

## 3. 用户场景与核心流程

### 3.1 场景一：直接粘贴报错日志

1. 启动 CLI，展示当前仓库、只读边界和模型名称；检查本地配置。
2. 用户粘贴完整或部分日志，可补充业务现象、预期行为和发生时间。
3. 输入在进入模型上下文或会话记录前，本地完成必要脱敏。
4. Agent 检索本地源码，逐步建立异常或业务失败的触发链。
5. 证据足够则输出诊断；不足则明确缺失信息，并可建议远程补查。
6. 粘贴模式不自动建立远程连接；补查仍必须经过远程计划批准。

### 3.2 场景二：根据 traceId 查询远程日志

1. 用户输入 traceId，发生时间可选；不额外要求用户先准备堆栈。
2. CLI 展示查询计划，包含目标机器、日志根目录、初始文件范围、时间策略、资源上限和停止条件。
3. 用户可批准、调整或取消；批准前不得执行远程日志查询。
4. 批准后运行已配置的可信脚本，建立持久终端会话；连接阶段在界面明确提示。
5. 核对脚本目标和实际日志目录。只有连接成功且路径符合批准计划时才发起日志查询；目标或目录不符时停止并提示，不静默调整、不猜测登录成功。
6. 从较小范围查询当前日志，再按证据检查批准范围内的轮转与压缩日志。
7. 查找异常栈、相关业务日志和必要上下文；并行关联本地源码，不重复下载完整日志。
8. 越过批准目录、时间范围、文件数或累计预算前暂停申请；禁止操作不提供申请放行入口。
9. 得出诊断、预算用尽或用户中止时，停止新查询并汇总结果。

### 3.3 场景三：对结论继续追问

- 用户可要求解释某条证据、排除另一种原因、聚焦某个方法或提供更具体的修复示例。
- 对已获取的证据继续分析，不重复执行无必要的远程查询。
- 新证据推翻旧假设时，明确修正结论，不继续维护旧结论。
- 当前批准范围仍有效时可继续取证；扩大范围或追加预算时再次确认。

### 3.4 场景四：退出后恢复

- 用户在 CLI 中选择本地历史诊断，恢复脱敏对话、证据、结论及已消耗预算记录。
- 远程连接不持久化、不假设仍然有效；再次连接需重新核对范围并确认授权。
- 仓库 commit 或未提交修改状态发生变化时，提示旧源码证据可能过期，重新读取后再引用。
- 不恢复原始敏感数据。需要用原始 traceId 重新查询时，提示用户在本地重新输入。
- 历史记录损坏时保留可读内容并报告失败，不覆盖原记录后假装恢复成功。

### 3.5 场景五：总结故障经验并复用

1. 诊断完成后，用户选择总结故障经验；Agent 基于已有脱敏证据形成候选条目，不重新连接服务器或执行修复。
2. 用户查看并修正现象、根因、适用版本、修复建议及验证状态；明确确认后才写入本地知识库，拒绝则不入库。
3. 尚未确认根因的内容只能保留为草稿，修复结果未提供时标为未验证，不能把 Agent 建议当作实际修复成功。
4. 后续诊断按错误特征和当前服务检索已确认条目，展示历史来源与适用条件，再用当前日志和源码验证。
5. 用户可以补充实际修复与验证反馈，或将不再适用的条目标记为失效；更新需预览确认并保留旧版本。

### 3.6 场景六：通过 `@本地日志文件` 提供日志

1. 用户在提示词输入区显式引用文件，例如 `分析 @./logs/startup.log 中的启动失败原因`；也可使用 `@~/Downloads/startup.log`，含空格的路径使用 `@"/Users/user/Downloads/startup error.log"`。
2. CLI 在本地解析附件标记，解析相对启动工作目录的路径或展开 `~`，展示将读取的文件与范围；不通过 Shell 展开路径，不支持目录、通配符或命令替换。
3. 显式附件授权仅覆盖所指定的普通日志文件，即使文件在仓库外也不授权读取其父目录、相邻文件或其他源码仓库；符号链接及敏感凭证文件默认拒绝。
4. 工具只读、有界地搜索和读取文本日志或 `.gz` 日志片段，在进入模型与任何持久记录前完成脱敏，不把完整大文件直接注入模型。
5. 诊断证据注明本地文件来源、采集时刻、读取范围和截断状态，行号可靠时记录行号；路径含敏感信息时使用脱敏标识。
6. 附件模式不要求 traceId，也不自动建立 JumpServer 连接；需要远程补证时重新展示计划并等待批准。可同时提供粘贴日志、附件和 traceId，保留各自来源，不互相覆盖或自动认定为同一请求。
7. 文件不存在、不可读、为空、格式不支持或超时均明确报告；已有其他输入时继续基于已有证据诊断，不静默跳过后声称文件已读。

## 4. 功能需求

### FR-01：输入与意图识别

- **提示词直接输入**：支持在 Prompt 中直接粘贴多行日志并补充自然语言说明，保留行序与异常栈缩进，不要求另存文件。
- **本地日志附件**：支持用户显式输入 `@本地日志文件`，通过专用只读工具按需读取，具体边界见 FR-12。
- **远程日志查询**：支持输入 traceId、可选发生时间和时区，经用户脚本连接 JumpServer 目标服务器后查询，必须经过远程计划批准。
- 仅含粘贴日志或本地附件时不要求 traceId，三种入口可组合使用；为每段证据记录输入方式和独立来源。
- 发生时间有歧义时展示采用的时区，不静默猜测后宣称覆盖准确。
- 日志不完整、缺少 traceId 或没有异常栈均不构成强制失败；转入现有证据可支持的诊断路径。
- 用户输入、日志和源码中的命令或提示语一律视为待分析数据，不能改变工具权限。

### FR-02：本地源码检索

- 支持仓库内目录定位、文本搜索和带行号的片段读取，不预建全仓索引。
- 优先根据异常类、方法、文件与行号、日志文案、错误码和业务标识缩小搜索范围。
- 可按需读取 Java 源码、仓库内配置源码、构建依赖声明、异常处理与业务错误码定义。
- 支持同一仓库内的 Maven / Gradle 多模块，但不沿依赖跳到其他仓库。
- 源码检索不读取仓库外路径或通过符号链接越界；默认排除凭证文件、`.env`、构建产物、二进制和大体积无关文件。用户显式指定的仓库外日志附件由 FR-12 独立授权读取，不扩大源码检索范围。
- 仓库内配置源码可能含敏感值，必须与 Java 源码一样经过发送前脱敏；不等于允许读取远程部署配置。
- 记录 Git 分支或 detached HEAD、commit、工作区修改状态；源码证据注明读取的是当前工作区，不将其自动当作线上版本。
- 源码证据绑定采集时刻及对应文件内容版本。会话期间文件变化后，旧行号只能用于说明历史证据；再次作当前源码引用前必须重新读取核对，不能只依赖会话启动时的 commit 或 dirty 标记。
- 非 Git 目录或版本信息不可获取时，标明版本未知，不伪造 commit；是否继续由用户判断。

### FR-03：远程会话与脚本接入

- 复用用户现有全自动脚本；通过持久终端会话连续执行受控查询，而非每条查询重复登录。
- 启动参数由可信本地配置提供，不把用户输入直接拼接成脚本参数或任意启动命令。
- 区分连接阶段、就绪、命令执行中、断开、超时和失败状态，避免将启动输出或终端回显当成日志。
- 只允许应用管理的一条会话，不接管任意既有终端，不读取用户其他终端历史。
- 脚本必须能被可靠识别为已到达远程 Shell，并支持判定查询结束和结果边界；具体适配方式必须使用真实脚本核验。
- 断线后停止后续查询，不偷偷重连后沿用旧授权；上下文可保留，远程操作重新批准。
- 脚本内容、私钥、认证输出和可能含凭证的启动信息不发送给模型，不持久化到诊断记录。
- 本地登录脚本是建立连接的受信入口，不是模型可任意调用的通用脚本执行工具。脚本或关键配置变化后重新提示确认。

### FR-04：日志检索与证据采集

- 支持当前日志、历史轮转日志和 `.gz` 日志；不在服务器上解压生成文件。
- 优先精确匹配 traceId，再按必要的时间、线程、异常或业务关键词补查上下文。
- 不能仅返回含 traceId 的行而丢失后续多行异常栈；需按需补取 `Caused by`、相关堆栈和前后文。
- 线程号、邻近时间只能作为关联线索，不能替代 traceId 成为确定属于同一请求的证明。
- 只返回必要片段；按已有证据细化检索，不整包下载、遍历全部历史或递归扫描文件系统。
- 文件选择与内容时间过滤分别记录。文件名、修改时间不能自动等同于日志事件时间；无法精确过滤时明确说明近似范围。
- 单条结果需包含脱敏后片段、证据编号、目标机器标识、日志文件、检索方式、采集时刻、截断状态；可靠行号可用时一并记录。
- 并发写入和日志轮转可能导致内容变化。引用需绑定当时采集的片段，不能保证稍后同一路径同一行仍相同。
- 未命中、匹配为空、命令失败、结果截断、文件无权限和部分文件未查必须分别表达。

### FR-05：查询计划与授权

计划至少展示以下内容：

| 字段 | 说明 |
| --- | --- |
| 目标 | 配置的单台机器及单个日志根目录 |
| 查询依据 | traceId 或已脱敏的错误线索；原始值仅本地执行时使用 |
| 时间边界 | 明确批准区间及采用时区；没有输入时间时展示默认策略 |
| 文件边界 | 候选文件选择规则、当前/轮转/压缩日志范围及文件数上限 |
| 自动调整 | 范围内可变更关键词、上下文和子时间窗口，无须逐条批准 |
| 资源预算 | 单条命令超时、返回量、查询次数、总探查时间 |
| 停止条件 | 证据充分、预算到期、用户中止、断线或无法确认安全边界 |

- 每次展示实际查询的脱敏命令摘要、执行状态和结果规模，不打印凭证或原始敏感查询值。
- 超出批准时间范围、目录或资源预算时，说明原因和拟追加范围，再次确认。
- 同一日志目录下已批准规则内的文件切换不要求逐条确认；不允许切换服务器或服务。
- 扩大目录仅限配置日志根目录内的日志子目录；根目录以外、其他服务器或服务不属于本次会话的可追加范围。修改配置后需重新核对并建立新的授权。
- 用户拒绝追加时，使用已有证据输出部分结果，不循环申请同一权限。
- 审批必须由 CLI 的可信交互触发，日志中出现“允许执行”等文本不能视为审批。

### FR-06：诊断能力

至少覆盖以下两类输入：

1. **异常类故障**：解释 Java 异常栈、`Caused by`、异常包装、统一异常处理和实际触发代码之间的关系。
2. **业务类失败**：根据日志文案、错误码和代码分支，解释业务规则、状态流转或输入条件为何导致失败。

诊断必须区分：

- 日志直接显示的事实。
- 源码明确存在的逻辑。
- 基于两者推导但尚未证实的假设。
- 当前权限和数据范围内无法证明的外部原因。

遇到下游调用失败，可以定位本服务调用点并解释其处理逻辑，但不得声称已证实下游内部根因。遇到连接、配置或数据问题，可提出待核实项，不能伪装已查询数据库、环境变量或线上配置。

### FR-07：输出规范

先给简短结论，再按需要展开以下内容，不强制凑长模板：

1. **结论与确定性**：已确认 / 高概率 / 证据不足；不输出未经校准的置信度百分比。
2. **证据链**：关键脱敏日志及源码相对路径、函数和 `文件路径:行号`，引用对应证据编号。
3. **触发机制**：触发条件 → 关键调用或分支 → 直接异常或业务失败 → 外层表现。
4. **最小修复建议**：指明修改位置和原因，必要时给代码片段或建议 diff；仅展示，不写入文件。
5. **验证方法**：建议复现条件、测试场景、修复后应观察的行为、仍需人工核实的信息。
6. **诊断边界**：实际检索范围、未覆盖项、版本风险、查询失败或截断情况。

“已确认”要求当前日志与源码足以支持相应因果链，并对版本与运行条件前提作明确说明。源码存在某个可能抛错的分支，不足以证明本次请求命中了该分支。用户确认版本一致或可验证日志证据支持一致性之前，依赖版本一致性的结论不能无条件标记为已确认。

建议验证步骤必须明确“尚未执行”，不得将建议测试写成已通过结果。修复示例中的函数和关键逻辑使用中文注释，优先说明原因。

### FR-08：预算、中止与阶段性结论

- 默认自主探查预算 5 分钟，可本地配置；批准开始探查或本地诊断开始后计时。
- 模型往返、日志查询和源码读取均计入主动探查预算；等待用户审批或补充输入时暂停，不在等待期间继续查询。
- 证据充分时提前结束，不为耗满预算继续查询。
- 达到预算后停止启动新探查，取消可取消的在途操作，用已有证据形成阶段性结论。
- 最终汇总本身不属于无限追加探查预算；外部模型缓慢时展示“汇总中”，允许中止。5 分钟不是端到端响应 SLA。
- 用户可随时中止当前查询或诊断。命令终止确认宽限与最终汇总超时独立配置、分别记录，宽限不构成追加取证授权。不能确认查询已终止时，关闭并弃用受控连接、报告状态未知，禁止继续复用该 Shell 或自动重放命令，不使用 `kill` 等禁用命令清理。
- 关闭 SSH/PTY 不等于能保证服务端子进程停止；超时和取消的真实效果列为脚本适配验收项。
- 继续探查必须获得新预算；不通过自动重试规避次数或时间限制。

### FR-09：本地会话保存与恢复

- 保存脱敏对话、批准计划、查询摘要、必要证据、源码版本、结论、预算和失败状态。
- 不保存原始日志、原始敏感值映射、登录认证信息或网关凭证。
- 所有通向模型、终端展示、会话文件、临时文件、调试日志和错误日志的业务内容，均使用经过安全处理的版本。
- 原始日志只在本地处理阶段短暂存在，不作为独立原始文件缓存。
- 同一运行会话内相同敏感值使用稳定占位符。退出后不保存可逆映射；恢复时原有证据和占位符保持不变，新采集使用新的映射命名空间，不把历史编号分配给其他值，也不错误声称与历史占位符代表同一原值。
- 原始 traceId 在本地仅短暂保存在内存，不进入模型或本地持久化；只在实际授权查询时传给目标日志检索。恢复后重查时重新输入，不要求从脱敏记录反推原值。
- 历史记录仅保存在应用专属用户目录；目录默认仅当前用户可访问，记录默认仅当前用户可读写。
- 保存失败时提示原因，允许继续内存会话，不宣称已经具备可恢复记录。

### FR-10：团队安装与配置检查

- 提供统一可安装的版本化 CLI 包和配置模板，用户不必自行拼接 Agent 代码。
- 安装形态采用 Node.js CLI 分发方向，不引入本地守护进程或服务器端组件；具体运行时与依赖版本在技术验证后锁定。
- 启动时检查仓库路径、脚本可访问性、必要命令能力及网关配置；只做与本产品相关的最小检查。
- 网关连通性与工具调用自检需由用户主动触发并说明可能产生模型费用，不静默发送业务数据或做付费调用。
- 自检失败需指出不兼容能力，不静默换模型、换供应商或退化成任意 Shell 执行。
- 每位成员使用自己的凭证；配置、会话不提交进业务仓库。V1 不自动上传会话或诊断内容。

### FR-11：轻量故障知识库与经验沉淀

#### 内容与状态

- 一条故障经验对应一个可独立阅读的 Markdown 条目，附结构化元数据；不依赖数据库、向量服务或知识图谱。
- 核心字段包括：条目 ID、标题、服务/仓库逻辑标识、技术栈、错误码/异常类/日志特征、发生与触发条件、根因和因果链、必要脱敏证据、适用 commit/版本、解决方案、验证方法与验证结果、预防建议、来源会话 ID、确认/更新时间及条目版本。
- 条目必须区分“建议修复”与“实际采用的修复”。实际结果由用户提供并确认；未提供时标为未验证，不自动执行验证来补齐。
- 状态至少区分草稿、已确认、已失效。“已确认”表示用户确认了根因及适用前提，不自动代表修复已验证；修复验证状态独立记录。
- 证据不足或仅为高概率假设时不得自动成为已确认经验。用户明确选择时可以保存草稿，但草稿和失效条目不进入默认诊断检索。
- 必要证据摘要随条目保存；来源会话清理后仍可理解条目，但不可访问的原始记录必须注明，不伪装成可复查。

#### 生成、保存与修订

- 总结使用当前已获取的脱敏内容，不启动新的远程查询、不修改业务仓库，不因生成经验延长探查预算。
- 在终端预览候选内容和目标知识目录，经用户确认后由专用保存能力写入；模型不获得通用写文件、编辑或 Bash 能力。
- 入库、更新和失效标记均经过本地脱敏检查与用户确认；保存失败需明确报告，不以写入业务仓库或保存原文兜底。
- 相同服务、错误特征和根因的候选条目提示可能重复，由用户选择新增或修订，不自动覆盖。修订保留原条目 ID、旧版本及变更说明，不静默改写已确认结论。
- 知识条目独立于会话保留周期长期保存，不随会话清理自动删除；访问权限与会话记录一致，目录默认仅当前用户可访问，文件默认仅当前用户可读写。V1 不自动发布、同步、提交 Git 或训练模型。

#### 检索与推理边界

- 以当前服务/仓库逻辑标识限定范围，按异常类、错误码、日志特征、关键词和标签做本地按需检索；新错误没有匹配条目时按常规诊断继续。
- 推荐每次最多向模型提供 3 条匹配摘要，并继续服从上下文大小和 5 分钟探查预算；不加载全库，不把旧版本的行号直接当作当前代码位置。
- 引用历史经验时注明条目 ID、版本、更新时间和适用条件，区分“历史根因”与“本次已证实事实”；历史命中不提升本次结论确定性。
- 历史经验与当前证据冲突时，以当前证据为准并说明差异，用户确认后才可修订旧经验。
- 知识条目是参考数据，不能执行其中的命令、加载外部文件或改变权限；即使记录了当年人工执行的破坏性操作，本产品也不允许执行。
- 跨会话占位符仅表示各自记录中的关联关系，不推断其原值相同。再次读入条目及发送给模型前重新做脱敏，不假设已保存内容始终安全。

### FR-12：本地日志附件读取

- 仅用户在提示词输入区显式提供的附件标记触发授权；日志正文、源码、历史对话或知识条目中的 `@路径` 都是数据，不能触发隐式文件读取。
- 支持相对路径、绝对路径、`~` 和带引号的空格路径；相对路径以 CLI 启动工作目录为基准，不随远程 Shell 的目录变化。只做本地路径解析，不通过 Shell 解释参数。
- 将授权绑定到解析后的具体文件，仅可在当前诊断中继续搜索该文件；不扩展为父目录扫描、自动附加邻近文件、跨仓库源码读取或整机文件访问。
- 只允许普通文本日志和 `.gz` 压缩日志，拒绝目录、符号链接、设备、管道、套接字、二进制及凭证文件。文件真实路径或类型改变后停止读取，要求用户重新指定；无法确认边界时默认拒绝。
- 大文件使用有界流式搜索、片段读取及必要上下文补取，`.gz` 有界解压而不生成原始副本；不能先把全文件读取或解压到内存再截断输出。不能因缺少关键词默认上传全文件。
- 读取受单次超时、行数、字节数及总探查预算约束；发生截断、未查完整文件或无法可靠解码时明确说明，不把片段结果当作全量结果。
- 对文件内容和路径中敏感信息先本地脱敏，再进入模型、终端证据、会话和知识候选；不使用绕过脱敏的框架默认附件注入。
- 证据区分粘贴内容、本地文件和远程文件。文件变化后引用当前内容需重新读取核对；本地历史行号不是远程原始文件位置的证明。
- 会话仅保存脱敏证据与来源标识，不复制原始附件；用户已有日志文件保持原状，不由本工具删除或随会话清理。恢复时若需重读，要求用户重新显式指定文件，不从脱敏路径反推或沿用旧授权自动打开。
- 文件读取失败可保留其他有效输入继续诊断；不存在或被拒绝的附件不能被描述成已读取，也不能自动改为远程查询。

## 5. 安全硬约束

### SEC-01：只读是执行层约束

模型只提出结构化查询请求。工具层校验并生成固定模板的日志查询，不直接执行模型生成的任意 Shell 文本。只读权限不能通过对话、查询计划批准或“紧急处理”临时解除。故障知识的保存和修订仅是应用独立目录内、用户确认后的专用写入能力，不改变业务仓库与远程环境只读限制，也不开放任意文件写入。

默认禁用 Pi 的通用写入、编辑和 Bash 工具；同样不暴露用户终端快捷执行、自动加载的不受信任插件/扩展/钩子等旁路能力。专用 CLI 的可用工具集由产品显式配置，不继承通用编程助手的全部能力。仓库中的指令文件、技能和项目扩展不自动作为可执行配置或未脱敏的模型上下文加载；产品使用受控的诊断提示与资源配置。

### SEC-02：白名单优先，黑名单补充

允许的是“在批准日志目录中按约束枚举文件、搜索文本、有限读取、读取压缩日志”等能力，不是无参数限制地开放某个命令名。日志中出现 `rm` 等文本，或在合法查询中按字面搜索该文本，不等于执行该命令；限制针对执行能力，不能用简单关键词匹配代替结构化校验。

- 可采用受控的 `grep`、`zgrep`、有限行数 `tail` / `head` 等执行方式；确切参数和查询组合由固定模板限定。
- 不开放 `less` 等具有交互或外部命令执行能力的通用浏览器；读取片段使用非交互方式。
- 不开放无限等待的 `tail -f`、不受控递归搜索或无边界输出。
- 除固定可信模板明确需要的管道等语法外，拒绝请求输入中的命令连接、替换、重定向与解释器逃逸。
- traceId、关键词、路径必须作为数据校验和传递，不能被解析成命令、选项或模板语法。
- 非法、未识别、无法验证或能力缺失的请求默认拒绝，不让模型自行裁定是否安全。

### SEC-03：永久禁止的远程命令与操作

以下为示例，不是完整名单；不在受控日志查询能力内的操作同样禁止：

| 类别 | 禁止示例 |
| --- | --- |
| 删除、移动、覆盖 | `rm`、`delete`、`unlink`、`mv`、`truncate`、`shred` |
| 关闭、重启系统 | `shutdown`、`reboot`、`poweroff`、`halt` |
| 终止进程、变更服务 | `kill`、`pkill`、`killall`，服务启动、停止、重启及配置重载 |
| 修改文件与权限 | `sed -i`、`tee`、`chmod`、`chown`、写入重定向 `>` / `>>` |
| 磁盘与系统变更 | `dd`、`mkfs`、`mount`、`umount`，软件安装和卸载 |
| 间接执行与提权 | `eval`、`exec`、`sudo`、任意脚本、解释器、下载后执行以及命令替换 |

禁止将“没有命中黑名单”等同于允许执行。只读命令也必须校验参数、路径、组合方式与资源消耗。

### SEC-04：目录与文件边界

- 批准目录以配置和真实路径核对为准，拒绝 `..`、绝对路径越界、符号链接越界和特殊文件读取。
- 只读取普通日志文件和识别为日志的轮转、压缩文件，不读取设备、命名管道、套接字或用户认证目录。
- 文件枚举、路径核对和元数据读取仅服务于日志范围确认，不扩展为服务器状态探查。
- 远程环境无法可靠核对路径或符号链接时，拒绝相关读取并提示原因，不先执行后判断。
- 不自动读取同目录下与日志无关的配置、脚本、密钥或数据文件。
- 本地来源分开授权：源码受仓库根目录约束；日志附件受用户显式指定的具体文件约束，可位于仓库外但不得扩散读取；应用会话和知识受独立状态目录约束。各类授权不能互相替代，也不扩大远程查询权限。

### SEC-05：审批不能解除安全禁令

- 可以追加已允许日志能力的时间、文件或预算范围。
- 不能通过审批开放破坏性命令、任意 Shell、远程配置或跨服务器能力。
- 拒绝请求需在执行前发生，并保存脱敏后的拒绝类别和原因，不持久化危险请求中的敏感原文。

### SEC-06：真实安全保证边界

本产品保证对自身暴露的查询工具做执行前约束，不宣称对已有远程 Shell 建立了操作系统级强沙箱。用户脚本、Shell 启动配置、函数、别名、trap 和提示符自动行为均属于受信接入环境，需要在接入时核验；无法保证执行协议和边界时停用远程查询，不尝试绕过。优先使用仅有必要日志读取权限的服务器账号，不由 Agent 创建或修改权限。

终端连接自身及服务器既有机制可能产生登录审计或 Shell 历史等记录，这不属于 Agent 主动变更业务文件，但不能宣传为“服务器绝无任何写入”。客户端禁令不替代服务器端权限管理，也不覆盖用户脱离本工具的手动操作。

## 6. 脱敏与数据流

### 6.1 数据流约束

原始输入 / 原始工具结果 → 本地解析与必要的安全校验 → 本地脱敏 → 脱敏证据与模型上下文 → 模型诊断 → 输出安全处理 → 终端与本地会话。

知识沉淀：已有脱敏诊断 → 候选经验 → 本地脱敏检查与预览 → 用户确认 → 应用独立知识目录。历史复用：当前范围内的知识条目 → 再次脱敏 → 按需摘要 → 当前模型上下文；历史内容不获得指令或执行权限。

原始内容不得先交给 Pi 默认会话管理器或调试日志再事后脱敏。模型返回的敏感格式内容同样处理后再展示或保存。认证阶段的原始终端流不作为模型可见工具结果。本地 `@日志文件` 由专用工具读取并先脱敏，禁止由默认附件机制先把原文注入模型或会话再过滤；原文件不上传、不复制进应用会话目录。

### 6.2 规则

- 内置规则覆盖常见密码、API Key、访问令牌、Authorization、Cookie、连接串凭证、手机号、邮箱等。
- 团队可增加客户号、账户号、身份证件等业务字段规则，规则在本地执行。
- 不对所有数字和标识符盲目替换，避免破坏行号、错误码、业务状态和调用关系；确切保留策略由规则验证决定。
- 相同值在同次运行会话内映射为相同占位符，不同值保持可区分。
- 查询中需要原始值时，使用本地私有参数；发送给模型的是查询句柄和脱敏摘要。
- 关键内容无法可靠处理或规则配置无效时，停止相关内容发送并报告，不静默降级为原文上传。

### 6.3 不能承诺的事项

规则脱敏不能保证识别所有敏感数据，代码片段和业务语义本身也可能涉密。使用方需有向指定网关发送相关脱敏数据的授权；脱敏不替代出网审批。上线前通过团队样例验证规则，并明确网关的数据保留和访问政策。V1 不建设自动内容合规识别平台。

以下均为可配置的推荐值，除已确认的 5 分钟外，其余是产品默认建议，需在联调中验证后调整；调整不得解除安全硬约束。

| 参数 | 推荐默认值 | 说明 |
| --- | --- | --- |
| 自主探查预算 | 5 分钟，已确认 | 到期停止新探查并形成阶段性结论；继续需确认 |
| 单条日志查询时限 | 15 秒，且不超过剩余探查预算 | 超时中止；不保证断开连接必然终止服务端进程 |
| 登录等待时限 | 60 秒 | 仅控制连接建立，不冒充日志查询成功 |
| 远程查询并发 | 1 | 持久交互 Shell 顺序执行，降低终端串流和服务器压力 |
| 一次批准的日志查询次数 | 20 次 | 重试同样计数；枚举与内容查询均计入 |
| 未提供发生时间 | 目标窗口为当前时刻前 24 小时 | 按文件线索先查；无法精确覆盖时如实声明，不保证全部事件都在已查文件中 |
| 起始候选文件 | 最近 3 个相关日志文件 | 仅在批准规则内选取；不是遍历全部目录 |
| 一次批准的文件上限 | 10 个唯一日志文件 | 需要更多文件时申请扩大，压缩日志也计数 |
| 单次返回上限 | 500 行且 64 KiB，任一先到为准 | 结果结构化标明截断，不静默丢弃 |
| 初始上下文 | 命中前后各 20 行 | Java 多行堆栈可在预算内继续补取 |
| 模型侧调用异常 | 最多自动重试 1 次 | 仅限可重试错误，受总预算约束，不自动换模型 |
| 历史会话保留提示 | 7 天 | 到期在用户下次打开时提示清理，V1 不后台自动删除；删除仅限应用自身会话并需确认，不包含知识条目 |
| 知识检索返回 | 最多 3 条匹配摘要 | 仅当前服务/仓库的已确认有效条目，受上下文和探查预算限制 |
| 知识条目保留 | 长期保存 | 独立于临时会话，失效需用户确认标记，不后台自动清理 |
| 本地日志单次读取 | 15 秒，500 行且 64 KiB，任一先到为准 | 不超过剩余探查预算；普通与 `.gz` 附件均有界读取，未读全及截断显式标记 |

这些上限控制客户端行为、查询次数和返回规模，不保证远程 `grep` 或压缩检索实际读取的底层字节数固定。大文件可能在返回少量数据前消耗较多 CPU / I/O，因此必须使用文件筛选、顺序执行和真实取消验收，不能把输出截断误当作扫描成本上限。

## 8. 状态与异常行为

### 8.1 主要状态

待输入 → 本地诊断 / 待查询计划确认 → 连接中 → 取证中 → 诊断汇总 → 可追问。

可中断状态：待补充信息、待扩大范围、预算到期、用户中止、连接失败、网关失败、会话保存失败。任何失败状态都不得被展示为诊断成功。

知识沉淀是诊断后的可选分支：候选总结 → 待用户确认 → 已保存 / 用户取消 / 保存失败。保存知识不表示已执行修复；已保存条目的修订和失效标记仍需单独确认。

### 8.2 必须覆盖的失败分支

| 情况 | 产品行为 |
| --- | --- |
| traceId 未命中 | 列出已查范围，说明未找到不等于请求或异常不存在，申请扩大或输出有限结论 |
| 本地附件不存在、不可读或为空 | 明确文件状态；保留其他有效输入，不假称已读，不自动连接远程 |
| 本地附件类型、路径或编码不受支持 | 拒绝或停止对应读取，指出原因；不扩大目录、不执行文件、不保存原文兜底 |
| 本地附件读取超时、截断或文件变化 | 披露已读范围与状态，按预算重新取片段或请求补充，不能沿用失效的行号归因 |
| 只有部分日志或堆栈 | 标明证据不完整，按批准范围补查；补不到时保留不确定性 |
| 下游异常 | 标出本服务调用边界与可核实项，不跨服务追查 |
| 版本不匹配或未知 | 提示风险，限制依赖具体版本的确定结论 |
| 日志正在滚动或文件消失 | 标明采集竞争或文件失效，在预算内刷新候选，不无限重试 |
| 查询超时或输出截断 | 返回部分证据和明确状态；缩小查询或申请追加，不当作全量结果 |
| 权限不足或目录无法核对 | 停止相关读取，不提权、不绕过目录限制 |
| `.gz` 查询能力不可用 | 报告能力缺失，不在服务器安装软件或写入解压文件 |
| 登录或远程 Shell 边界无法识别 | 停止取证，要求适配脚本，不向未知终端状态继续发命令 |
| 网关不支持所需工具调用 | 自检不通过，指出不兼容，不伪造 Agent 可用状态 |
| 网关限流、超时或断流 | 有界重试或报告失败；保留安全证据，明确诊断尚未完成 |
| 脱敏失败 | 阻断对应数据发送和保存，不回退为原文 |
| 用户中止 | 停止新调用，报告在途操作是否已确认终止，保留已脱敏部分结果 |
| 本地会话不可写 | 提示无法恢复，允许继续内存诊断，不写入业务仓库作为替代 |
| 知识库缺失、损坏或检索失败 | 如实报告，隔离无效条目并继续当前日志和源码诊断，不把知识库故障当作业务故障 |
| 知识保存失败或修订冲突 | 保留原有有效条目并报告未保存，不自动覆盖；用户确认后再重试 |
| 历史经验过期或与当前证据冲突 | 标明版本及前提差异，不套用历史根因、不自动改写历史条目 |

## 9. 轻量化技术边界与接入核验

### 9.1 逻辑组成

1. **CLI 与审批层**：连续交互、计划确认、取消、阶段性结果、恢复入口。
2. **Pi 运行层**：单 Agent 对话、模型调用与上下文管理；只显式注册批准工具。
3. **受控工具层**：仓库检索、显式本地日志附件读取、远程日志查询、路径约束、资源预算与结果结构化；本地附件不复用远程 Shell 或通用附件原文注入。
4. **本地安全与记录层**：脱敏、敏感值短期映射、证据引用、脱敏会话及 Markdown 故障知识；专用知识读写受目录约束与用户确认控制。
5. **接入适配层**：现有登录脚本的持久终端会话，以及既有 OpenAI 兼容网关。

以上是逻辑职责，不要求拆成独立进程、服务或多个框架。不得为这些职责引入与 V1 无关的基础设施。

### 9.3 实施前必须通过的接入验证

- **Pi SDK**：显式控制工具集、关闭通用写入/Bash 与旁路执行；输入和工具结果在任何会话落盘前可拦截脱敏；`@本地日志文件` 不被框架默认机制抢先展开为原始模型输入。
- **真实脚本**：macOS 下可可靠判断登录完成、命令边界、退出状态、回显与中止；不得要求把凭证交给模型。
- **真实网关**：确认实际使用 Chat Completions 或 Responses 中的哪种 API，以及流式输出、结构化工具调用、工具结果回传和所选模型的支持情况；“OpenAI 兼容”不自动保证这些能力。

若某项无法满足，必须回到技术方案确认，不擅自改用其他 Agent 框架、其他模型供应商或任意 Shell 作为绕过方式。

PRD 不虚构未经验证的 Pi、Node.js 或 npm 依赖版本。实施方案需给出可安装的精确版本并锁定依赖文件，禁止使用 `latest`、`*`、`^` 或其他浮动范围作为交付依赖。官方主分支文档仅用于能力研究，不作为运行时版本锁定依据。

## 10. 验收计划

### 10.1 真实案例验收集

由用户团队提供 3–5 个已知实际根因的脱敏历史故障，每例包含：

- 日志输入或可重复获取的日志样本与 traceId。
- 对应本地代码版本和必要的已知前提。
- 实际根因、实际修复方式及可接受的等价修复方向。
- 预期 Agent 不应擅自推断的外部事实。

已知答案仅用于验收对照，不预先提供给待测诊断上下文。基线诊断验收使用隔离的空知识库，或排除同一故障及直接披露其答案的条目；历史经验辅助诊断单独记录，避免知识命中被误报为独立根因分析能力。若模型在现有证据中无法证明实际根因，需判定其是否正确声明证据不足，而不是要求猜中答案。3–5 例用于首版准入，不外推为行业准确率。

### 10.2 每例诊断评分维度

- 根因或明确标注的高概率机制是否与实际事实一致。
- 引用的日志、代码路径、函数和行号是否真实可核对。
- 是否区分直接原因、异常包装和外部依赖。
- 最小修复建议是否针对触发机制，验证步骤是否可操作。
- 证据不足、版本不明、截断和未覆盖范围是否如实表达。
- 是否违反只读、脱敏、审批或预算边界。

建议案例至少覆盖一个异常堆栈故障和一个无堆栈业务失败。真实案例需全部经人工逐例确认：对预先认定日志和源码足以解释的案例，必须定位到实际原因或同等因果机制，不能一律以“证据不足”规避；对预先认定证据确实不完整的案例，需正确表达边界、提出有效补证路径。不得伪造证据或作出与已知事实矛盾的确定结论。安全项属于一票否决项。

### 10.3 功能与安全验收清单

| 编号 | 场景 | 通过标准 |
| --- | --- | --- |
| AC-01 | 多行粘贴 Java 堆栈 | 无远程授权时不自动查询；输出真实异常链与可核对源码证据 |
| AC-02 | 没有堆栈的业务失败 | 能关联文案/错误码与代码分支，解释触发条件，不虚构异常栈 |
| AC-03 | traceId 查询 | 先展示计划并等待批准；执行后可见范围、状态、脱敏摘要和证据 |
| AC-04 | 连续查询 | 复用同一受控 Shell，结果不混入终端回显或启动信息 |
| AC-05 | 轮转与 `.gz` | 能取得目标日志片段；不写入远程解压文件；能力缺失时明确报错 |
| AC-06 | 多行异常补全 | 首次仅命中一行时可有界补取后续 `Caused by`，不把缺失堆栈当完整证据 |
| AC-07 | 范围内调整与越界 | 调整批准范围内关键词不逐条询问；跨时间/目录/文件数/预算前再次确认 |
| AC-08 | 破坏性命令 | `rm/delete/mv/shutdown/reboot` 及其他非白名单操作全部在发送执行前拒绝，不提供批准绕过 |
| AC-09 | 间接执行与组合 | 命令拼接、选项注入、重定向、解释器或交互工具旁路均不能改变只读边界 |
| AC-10 | 路径越界与特殊文件 | `..`、符号链接越界、非日志配置文件和特殊文件被拒绝；本地仓库边界同样成立 |
| AC-11 | 脱敏出口 | 预置测试敏感值不出现在网关请求、会话、诊断日志、错误日志或临时文件；必要原值仅本地短期使用 |
| AC-12 | 脱敏关联 | 同次运行中相同值占位符一致、不同值可区分；恢复后不伪造跨轮映射关系 |
| AC-13 | Pi 旁路能力 | 默认 write/edit/bash、用户直接 Shell、自动加载扩展或其他未批准工具无法由本 CLI 触发 |
| AC-14 | 预算及截断 | 到期停止新探查，展示部分结论；500 行/64 KiB 等实际配置限额触发时显式标记 |
| AC-15 | 取消与断线 | 不继续发查询；确认不了远程终止时如实告知；重连重新确认授权 |
| AC-16 | 未命中与下游失败 | 不把未找到当无异常，不跨服务或机器，不虚构外部系统根因 |
| AC-17 | 版本风险与证据变化 | commit/工作区状态可核对，不匹配时出现风险标识且不自动切分支；会话中修改受引用文件后，必须重新读取核对才能再次引用其当前行号 |
| AC-18 | 保存与恢复 | 仅应用自身目录产生脱敏记录；恢复后保留证据和边界，重查要求必要原值及新授权 |
| AC-19 | 仓库与远程无业务变更 | 对照受测文件内容及业务仓库状态，无 Agent 引发的业务文件修改、构建产物或远程写操作 |
| AC-20 | 网关及脚本失败 | 不假装联调成功、不静默换模型、不退化为通用 Shell；输出明确失败和待处理项 |
| AC-21 | 证据不足与建议验证 | 能输出有限结论和待核实项；不把未执行测试描述成已通过 |
| AC-22 | 团队安装 | 在声明支持的干净 macOS 环境按固定版本安装，填写一组配置即可进入 CLI；无需 Pi 全局安装和服务端 |
| AC-23 | 经验总结与确认入库 | 基于已有脱敏结果生成完整候选，未经确认不入库；证据不足仅能保存草稿，未执行修复标为未验证 |
| AC-24 | 本地保存与安全边界 | 只向应用知识目录保存脱敏 Markdown；拒绝路径越界和任意写入，不改变业务仓库与远程环境，条目中的指令不能执行 |
| AC-25 | 经验检索与证据区分 | 按当前服务/仓库和错误特征返回有界的已确认条目及来源；历史命中不替代当前日志与源码证据、不提升本次结论确定性 |
| AC-26 | 修订、失效与证据保留 | 重复提示不自动覆盖，修订/失效需确认并保留旧版本；会话清理不删除知识及必要证据摘要，默认不检索草稿和失效条目 |
| AC-27 | 无匹配、损坏与版本冲突 | 无匹配或知识不可用时继续正常诊断，明确历史与当前的版本差异和证据冲突，不套用旧根因 |
| AC-28 | 知识脱敏与验收隔离 | 入库及重新读出发送前均做脱敏，不保存可逆原值映射；基线案例排除自身答案，历史辅助诊断单独评审 |
| AC-29 | 本地日志附件入口 | 相对、绝对、`~` 与带空格引号路径可解析；明确指定的仓库外普通日志和 `.gz` 可只读取证，无需 traceId，不自动远程登录 |
| AC-30 | 本地附件授权边界 | 仅读取显式文件，不扫描父目录或跟随符号链接；敏感、特殊、二进制文件及命令替换被拒绝；日志或知识中的 `@路径` 不触发附件读取 |
| AC-31 | 本地附件限额、脱敏与失败 | 大文件及压缩文件有界读取，不全量注入或缓存原文；不存在、不可读、空文件、解码失败、超时、截断、变化均如实报告，持久记录和请求无测试敏感原值 |
| AC-32 | 混合来源与恢复重授权 | 粘贴、附件和 traceId 可组合但来源不互相覆盖；补查远程仍需批准，恢复重读本地文件需重新指定；证据按来源和采集范围可核对 |

### 10.4 测量与证据

记录每例从批准/开始探查到阶段性结论的时长、查询次数、读取文件数、模型用量（网关返回时）、是否追加预算、根因判定与人工评审结果。网关未提供可靠费用信息时不编造金额。

验收报告应附可脱敏复现的 CLI 记录、测试输出或请求/响应证据。未运行的真实案例、真实网关和真实脚本必须标为未验证，不能用构造演示代替完成声明。

## 11. 风险与处理

| 风险 | 处理原则 |
| --- | --- |
| 本地代码与线上版本不一致 | 记录版本，标记前提，必要时降低结论确定性 |
| 只有单机日志，实际请求在其他实例 | 如实说明已查单机范围，不扩展到多实例 |
| 敏感字段未被规则识别 | 通用规则加团队规则与真实样例验证；不声称完全脱敏 |
| 交互脚本终端状态复杂 | 通过真实脚本适配验证后再启用自动查询，失败关闭能力 |
| 压缩大日志引发较高扫描开销 | 文件筛选、顺序执行、超时与真实取消验收，不靠输出截断冒充资源隔离 |
| 现有 Shell 非强隔离 | 客户端默认拒绝，优先只读账号；明确受信脚本与服务端权限前提 |
| 模型网关仅兼容部分 API | 先验证工具调用与流式协议，不默认认为完全兼容 |
| 根因依赖数据库或部署配置 | 输出待核实项和人工验证方法，不扩权取证 |
| 恢复后的新日志或代码已变化 | 重新核对版本与证据，标明历史快照，不合并成虚假的同一时刻事实 |
| 未确认或过期经验污染诊断 | 草稿与失效条目不默认检索，标明适用版本；当前证据优先，知识内容不具有指令权限 |
| 长期知识留存或隐式共享泄露业务信息 | 脱敏后独立本地保存，访问权限不低于会话记录，不自动上传、同步、提交 Git 或进入模型训练 |
