# Code standards（审查必查）

从 LESSONS 晋升或团队底线。PR 不满足则必须改或说明例外。

## 变更范围

- 一次 PR 只做一类事：修 bug、加功能、重构或配置，不混大杂烩。
- 修复要覆盖同类路径，不只改报告中的那一个调用点。
- 每次变更的commit要非常详细的描述。 
- 变更可以自动提交commit，但是不允许操作push.

## 数据、状态与副作用

- 读失败、解析失败、子进程失败和请求失败必须进入错误路径；不能当成 empty 继续写入或展示。
- 可重试写操作必须有业务幂等约束或去重记录，不依赖调用方不重试。
- 外部副作用放在本地事务外，或在本 CLI 中直接禁止；无法撤销的远端变更要有补偿、重试和幂等策略。
- 文件、行数、远程输出达到上限时必须标记截断或未覆盖，禁止静默丢弃后报告“未找到/完整扫描”。

## 契约与兼容

- 已发布 CLI 参数、stdout/stderr 输出和退出码默认加字段不删字段；删除或改语义必须写迁移与版本策略。
- 共享类型、`src/ports/` 端口、CLI 参数、输出契约与 `templates/` 变更前，必须搜索 `src/`、`tests/`、`README.md` 与 `install.md` 的全部调用方。

## 测试与验收

- 有行为变更就要有在旧逻辑上会失败的测试。
- 测试不访问真实第三方、真实服务器或真实凭证；按项目已有风格使用测试替身。
- main 上红的测试当作现网缺陷：先修复或立项，不在红测试上继续堆功能。
- 构建与 `npm run typecheck` 通过不等于验收通过；关键路径必须运行 `npm test`。

## 安全与配置

- 密钥不进库；日志、错误和测试快照输出必须脱敏。
- `~/.config/finch/.env`、`models.json` 权限为 0600；模板只写变量名，不写真实值。
- 远程登录、远程查询和本地文件读取都必须经过各自的路径/授权/预算校验，不靠“工具只暴露了只读方法”的口头保证。
- 环境相关地址、开关和凭据必须有默认策略，并允许本地或测试环境覆盖。
